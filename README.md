# Лабораторная работа 1. Поиск частых наборов алгоритмом Apriori

Программа на Kotlin выполняет поиск частых наборов объектов (frequent itemsets)
в наборе данных о покупках в супермаркете (`baskets.csv`, 7501 корзина, 115 товаров)
с помощью алгоритма **Apriori**, а также строит ассоциативные правила
с метриками **support**, **confidence** и **lift**.

## Задание

Разработать программу, которая выполняет поиск частых наборов объектов в заданном
наборе данных с помощью алгоритма Apriori. Список результирующих наборов содержит
как наборы, так и значение поддержки для каждого набора. Параметрами программы
являются набор данных, порог поддержки и способ упорядочивания результирующего
списка наборов (по убыванию значения поддержки или лексикографический).

Эксперименты: на фиксированном наборе данных `baskets.csv` варьируется пороговое
значение поддержки (1%, 3%, 5%, 10%, 15%); выполняется визуализация результатов —
сравнение быстродействия при изменяемом пороге и количество частых наборов
различной длины при изменяемом пороге.

## Как запустить

В IntelliJ IDEA открыть проект (каталог `lab1`) и запустить `src/Main.kt`.
Рабочая директория — корень проекта, данные читаются из `src/data/baskets.csv`.

Параметры эксперимента задаются в начале `main()`:

```kotlin
val minConfidence = 0.3                                  // порог достоверности правил
val thresholds = listOf(0.01, 0.03, 0.05, 0.10, 0.15)    // пороги поддержки
```

## Результаты экспериментов

| Порог поддержки | minSupport | Длина 1 | Длина 2 | Длина 3 | Всего наборов | Время работы |
|---|---|---|---|---|---|---|
| 1%  | 76    | 74  | 170 | 17 | 261 | ~0.9–1.8 c |
| 3%  | 226   | 36  | 19  | —  | 55  | ~170 мс    |
| 5%  | 376   | 25  | 3   | —  | 28  | ~90 мс     |
| 10% | 751   | 7   | —   | —  | 7   | ~16 мс     |
| 15% | 1126  | 5   | —   | —  | 5   | ~15 мс     |

Выводы:

* при снижении порога поддержки количество частых наборов и время работы
  растут нелинейно (каскадный эффект: больше одиночек → больше пар → больше троек);
* наборы длины 3 появляются только при пороге 1% — для совместной встречаемости
  трёх товаров в ≥76 корзинах каждый из товаров должен встречаться очень часто;
* при порогах 10% и 15% выживают только одиночные товары (минеральная вода — 1788
  корзин, макароны — 1410, яйца — 1348 и т.д.).

Примеры ассоциативных правил (порог поддержки 1%, confidence ≥ 0.3):

```
{травы и перец} -> {говяжий фарш}                 support = 1.6%  confidence = 32.3%  lift = 3.29
{замороженные овощи, минеральная вода} -> {молоко} support = 1.1%  confidence = 31.0%  lift = 2.39
{суп} -> {молоко}                                  support = 1.5%  confidence = 30.1%  lift = 2.32
{говяжий фарш} -> {макароны}                       support = 4.0%  confidence = 41.0%  lift = 2.18
```

## Алгоритм

Классический Apriori (Han, Kamber, Pei — «Data Mining: Concepts and Techniques», разд. 6.2):

1. **L1** — подсчёт поддержки каждого товара, отбор прошедших порог;
2. **aprioriGen(L(k-1)) → C(k)** — генерация кандидатов: *join* (склейка пар наборов
   с общим префиксом длины k-2) и *prune* (отсечение кандидата, у которого есть
   нечастый (k-1)-поднабор — свойство Apriori);
3. сканирование базы и отбор кандидатов с поддержкой ≥ порога → **L(k)**;
4. повторение, пока уровень не опустеет.

Диаграммы экспериментов (`charts.html`, снимок `img/stat.png`):

1. время работы алгоритма при изменении порога поддержки;
2. количество частых наборов различной длины при изменении порога поддержки.
